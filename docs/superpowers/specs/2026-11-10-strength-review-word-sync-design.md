# 强化系列审计 Word 同步与再生成防覆盖设计

**日期**：2026-11-10  
**范围**：修复 `STRENGTH_SERIES_REVIEW.docx` 缺少 17 节补记的问题，并防止基础再生成删除既有 resolution 或补记；不开展 751 份文档的全库审计，不新增或提升任何数学、物理主张。

## 已核事实与问题

- 当前 Markdown 含 K1a、K1b 和 15 个 K2 补记，共 17 节；当前 DOCX 的这 17 节全部缺失。
- `verify_strength_delivery.py` 在该缺节状态下仍实际返回 `16/16 pass`，说明旧验证没有正文同步检查。
- `render_strength_review.py` 会重写两份机读总账和 Markdown，但当前生成逻辑只产生早期基线；直接重跑可能覆盖后续成果。
- 本次修复不得把历史 OOXML 验证通过或旧视觉 QA 当作当前内容完整性的证据。

## 方案比较与决定

1. **从当前 Markdown 完整重建 DOCX（采用）**：以当前 Markdown 为唯一正文来源，重新生成目录、公式、表格和后续补记。优点是内容来源一致，避免逐节拼接造成层级和目录错位；代价是必须重新执行完整结构与视觉验收。
2. **在旧 DOCX 末尾拼接 17 节**：保留旧包更多字节，但需要处理书签、目录、编号、公式和链接，且无法解决生成源再次覆盖的问题，不采用。
3. **只修改旧验证文案**：不能修复正文，也不提供防回归能力，不采用。

## 工作边界

- 保留当前 DOCX 的 Git 历史与只读工作副本，不删除历史证据。
- 不在实际审计目录运行旧基础渲染器；防覆盖测试只在隔离副本中运行真实渲染。
- 不重写 55 篇初审的方向角色、新颖性边界、未竟工作或优先级。
- 不把 Word 同步完成解释为任何数学证明、外部查新或全库审计完成。
- 只提交最终 DOCX、持久测试、最小生成修复、验证记录与 QA `report.json`；解包目录、基线副本和页面图片不提交。

## 组件与职责

### 1. Word 内容同步测试

新增独立测试文件，读取当前 Markdown 和实际 DOCX：

- 从 Markdown 提取 K1a、K1b、K2 的 17 个补记标题及正文边界。
- 从 DOCX 正文读取实际文本，逐标题报告缺失项。
- 额外检查最后的商层标题和 `60/60` 记录，防止只保留早期补记。
- 在当前 DOCX 上必须得到包含 17 个缺失标题的预期失败；修复后必须全部存在。
- 另设原生结构断言：目录域、`<m:oMath`、真正表格、中文页眉和 `PAGE` 页码。

### 2. 再生成防覆盖测试

新增独立测试文件，在 `research/` 下建立与真实审计目录同层级的临时副本，使脚本的工作区解析保持不变：

- 仅复制运行所需脚本、`math-focus.json`、当前两份总账和当前 Markdown，不复制 QA 图片或解包目录。
- 在临时副本中真实执行 `render_strength_review.py`，不触碰实际审计文件。
- 验证每个既有 `resolution_2026_11_10` 和其他非基线字段仍属于原论文 ID。
- 验证总账摘要中的既有 resolution 汇总字段未丢失。
- 验证 17 个补记标题及正文在再生成后保持原顺序且无重复。
- 当前实现必须先因 resolution 或补记丢失而失败；最小修复后在隔离副本中通过。

### 3. 最小生成修复

只改变保留逻辑，不改变 55 篇基线裁决：

- 对记录按 ID 合并：新生成的基线字段保留新值，既有额外字段（尤其 `resolution_2026_11_10`）保留；不得凭 ID 顺序猜测对应关系。
- 对摘要采用“基线字段刷新、额外 resolution 字段保留”的合并方式，不把历史完成标志复制到基线状态字段。
- 对 Markdown 仅保留已存在的 K1a、K1b、K2 补记及其正文，保持原顺序；若任一节会丢失或重复，必须显式失败，不静默修补。
- 修复只在隔离副本验证，不在本任务中重跑实际目录的基础渲染器。

### 4. DOCX 重建与版式

- 从当前 `STRENGTH_SERIES_REVIEW.md` 生成完整 DOCX，包含全部 17 节。
- 使用既有 Pandoc、CJK reference、页面和表格宽度修正脚本。
- 保留原生公式、真正表格、目录域、中文页眉和原生页码。
- 使用工作副本流程保存基线；若发生交换失败，保留备份并先恢复工作副本，不删除交换目录或强行覆盖。

## 数据流

1. 当前 Markdown＋当前 DOCX → Word 内容测试复现 17 节缺失。
2. 当前总账＋隔离副本 → 真实再生成测试复现 resolution／补记丢失。
3. 最小保留逻辑修复 → 隔离再生成测试通过。
4. 当前 Markdown → 完整 DOCX 重建 → 内容测试通过。
5. 最终 DOCX → OOXML／OPC 验证 → 单次最终视图渲染与逐页检查 → 更新验证日志。

## 错误处理

- 测试路径错误、DOCX 无法解包、临时目录工作区解析错误或脚本未实际运行，均属于测试错误，不得算作预期 RED。
- 预期 RED 必须分别来自“17 节正文缺失”和“隔离再生成丢失 resolution／补记”。
- 缺图、缺字体、目录域缺失、表格数量异常或公式不是原生 OMML，必须阻止交付。
- 视觉渲染不可用时如实披露，不用 LibreOffice 替代；渲染可用时必须检查联系表、所有页面、近空白页和 content-loss。
- 任一既有 resolution、补记或开放边界丢失时停止，不通过手工删改测试来放行。

## 验收标准

- 两类新测试均先保存真实失败记录，再于最小修复后通过。
- 最终 DOCX 含全部 17 节，商层标题与 `60/60` 记录存在，无重复补记。
- 隔离再生成不删除任何既有 resolution、额外摘要字段或补记。
- `docx.py validate` 返回 `PASSED`；最终视图全部页面已检查，无未解释的近空白页、裁切或正文丢失。
- 验证日志记录实际命令、退出码、关键输出和证据边界；远端提交哈希复核一致。
- 本任务只关闭“Word 内容同步”和“再生成防覆盖”两个工程缺陷，751 份全库审计与重点数学研究继续保持独立开放。
